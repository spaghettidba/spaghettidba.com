Next week, on Saturday 28, make sure you don't miss <a href="https://www.sqlsaturday.com/367/eventhome.aspx">SQLSaturday Pordenone</a>!

<img class=" aligncenter" src="http://www.sqlsaturday.com/images/sqlsat367_web.png" alt="" width="236" height="115" />

Pordenone is the place where the Italian adventure with SQLSaturday started, <a href="https://www.sqlsaturday.com/176/eventhome.aspx">more than two years ago</a>. It was the beginning of a journey that brought many SQLSaturdays to Italy, with our most successful one in <a href="https://www.sqlsaturday.com/355/eventhome.aspx">Parma</a> last November.

Now we're back in Pordenone to top that result!

We have a fantastic <a href="https://www.sqlsaturday.com/367/schedule.aspx">schedule</a> for this event, with a great speaker lineup and great topics for the sessions. Everything is set in the right direction to be a great day of free learning and fun.

I will have two sessions this time:

<strong>SQL Server Security in an Insecure World</strong>

In this session I will talk about security, with a general introduction to the topic and then I'll go straight to demonstrate some of the vulnerabilities that attackers could use to take over your server. Yes, I'll be demonstrating SQL-Injection attacks: SQL-I is still a top security issue, even if we're in 2015. Everyone must be aware of the risks and take action immediately.
I will also describe the security features available in SQL Server to lock down the server as much as possible, but the key concept I will try to drive is that security is a process, not a feature.
If you want to find out more, join me at 12:00 PM in room S7.

<strong>Extending the Data Collector to Monitor SQL Server effortlessly</strong>

In this session I will try to promote one of the least used features in SQL Server: the Data Collector. It doesn't have all the bells and whistles of the expensive monitoring suites, but it does the job pretty well. Things start to be painfully difficult when you try to extend it with additional collection sets, but the good news is that there's an open-source project that provides a GUI to manage and customize the collection sets. The project is called <a href="http://extendedtsqlcollector.codeplex.com/">ExtendedTSQLCollector</a> and it does much more than just adding a GUI to the Data Collector: it also provides two additional collector types to collect data from LOB columns (in case you're wondering, no - the vanilla Data Collector doesn't support LOB columns) and Extended Events sessions.
I will also demonstrate a convenient way to centralize and extend the Data Collector reports to create a reporting and alerting solution for free.
Sounds interesting? Join me at 4:30 PM in room S7.
